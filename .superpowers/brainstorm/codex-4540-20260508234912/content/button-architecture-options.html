Unified Button Direction

`src/components/ui/button.tsx` становится базой. Вопрос сейчас: как совместить её со старыми пропсами и какой визуальный тон взять за основу.

Conservative Merge

Оставляем красивую базу в `components/ui/button.tsx`, а старый `shared/ui/Button` превращаем в совместимый адаптер.

Плюс: минимум риска. Минус: всё ещё будет два уровня API, пусть и с разной ролью.

Balanced Hybrid

Делаем одну главную кнопку на базе `cva`, но сохраняем старые пропсы как совместимые алиасы и переносим tooltip внутрь компонента.

Плюс: единая точка входа и переиспользуемость. Минус: API нужно аккуратно спроектировать, чтобы он не стал слишком широким.

Expressive Hybrid

Та же идея единой кнопки, но со смелее поданной визуальной системой: теплее цвет, глубже тени, сильнее состояние hover/active.

Плюс: заметнее характер. Минус: может выбиваться, если остальной UI у вас сейчас спокойнее.
Recommended Architecture
Core button `variant`, `size`, `asChild`, `leftIcon`, `rightIcon`, `tooltip`, `children`
Compatibility layer `buttonText` maps to `children`, old props still accepted during migration
Migration path New screens use modern API, old screens keep working without urgent rewrite
Decision We Need

Сейчас важно выбрать не реализацию по строчкам, а направление:

  • оставляем wrapper как адаптер
  • или переносим legacy-пропсы прямо в базовую кнопку
  • и какой тон стилизации ближе проекту
